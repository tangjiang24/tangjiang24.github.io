前言

room 是在sqlite基础上提供了一个抽象层，方便数据库操作，并支持协程、flow。

创建数据实体

  • 必须用 @Entity 注解，会自动映射为数据库表；
  • 默认表名为实体类名，可通过 tableName 重新指定；
  • 主键用@PrimaryKey 注解，可指定是否自增，默认不会；
  • @Ignore 会在声称表结构时忽略此字段；
  • 数据库列名默认为实体类字段名，可通过 @ColumnInfo(name = “ XX”)重新设定；

创建db

  • 该类必须带有 @Database 注解，该注解包含列出所有与数据库关联的数据实体的 entities 数组；
  • 该类必须是一个抽象类，用于扩展 RoomDatabase；
  • 对于与数据库关联的每个 DAO 类，数据库类必须定义一个具有零参数的抽象方法，并返回 DAO 类的实例；

注意：如果您的应用在单个进程中运行，在实例化 AppDatabase 对象时应遵循单例设计模式。每个 RoomDatabase 实例的成本相当高，而您几乎不需要在单个进程中访问多个实例。

如果您的应用在多个进程中运行，请在数据库构建器调用中包含 enableMultiInstanceInvalidation()。这样，如果您在每个进程中都有一个 AppDatabase 实例，可以在一个进程中使共享数据库文件失效，并且这种失效会自动传播到其他进程中 AppDatabase 的实例。

CRUD基本操作

注意：以下分类是按照SQL操作类型分类，而不是按Room的注解来分类的。

Insert 插入数据

  • @Insert注解方法可方便实现数据的插入（单个、多个）；

  • 注解包含 entitie 和 onConflict，entity为目标实体，onConflict 为冲突时改如何处理；

  • 返回值为 Long类型或者 List<Long>，表示插入的行id；

  • 可通过传递自定义实体参数来实现快速添加部分字段内容，前提为其它字段都可以为null，且参数实体字段名和目标实体字段名相同；

onConflict 控制，有三个值可选：

  • OnConflictStrategy.ABORT ：默认值。出现冲突，撤销当前操作记录。但是已添加的数据不影响，并停止后续的操作。

  • OnConflictStrategy.REPLACE ：出现冲突，将已有数据，进行更新。替换成最新记录。继续执行后面的语句。

  • OnConflictStrategy.IGNORE： 出现冲突，保留已有数据，本次操作不生效。继续执行后面的语句。

update更新

  • Update注解可方便实现数据的更新（单个、多个）
  • 同样包含entitie 和 onConflict；
  • 返回值为 int，表示更新的数量（当更新实体在数据库中不存在时）;
  • 可通过传递自定义实体参数来实现快速更新部分字段内容，前提为参数实体字段必须包含目标实体的主键；

delete删除

  • Delete注解可方便实现数据的删除（单个、多个），但对于复杂情况删除需要用 @Query注解配合SQL语句；
  • 只包含entitie；
  • 返回值为 int，表示删除成功的数量;
  • 可通过sql语句进行条件删除外，也可通过自定义参数实体进行条件删除；

query查询

  • 通常通过@Query 及SQL语句进行条件查询;
  • 返回值可定义为集合或者单个实体；定位为集合若没有查到则会返回空集合，定位为单个实体，如果查到数据返回第一条数据，否则返回null；

数据库升级

Room 通过Migration类来执行升级的操作，我们只要告诉Migration类改了什么就行，比如新增字段或表。大致流程为：修改版本号 -> 添加 Migration ->修改实体-> 添加给 databaseBuilder。

注意：Migration的实现中SQL语句必须和@entity注解的实体相对应，包括字段名，是否自增，是否为null等约束。

  3. 修改对应的实体与升级后相匹配，比如新增实体或者更改实体字段等；

  4. 将Migration添加给databaseBuilder
