Kotlin协程基础

引言

之前我们在异步编程中都用的是线程，线程是基于操作系统的，因此它是非常重量级的，过多的线程一定会让我们的 程序不堪重负。而kotlin在语言层面为我们提供了协程，允许我们在单线程下模拟多线程的编程效果，同时开启上万个协程完成并发任务不是梦！

可以理解为协程就是一种轻量级的线程 。

suspend函数

即挂起函数，通过suspend关键字可以将任意函数声明为挂起函数。挂起函数只能被挂起函数或者协程来调用，普通函数则无法调用，比如：

由于delay()是一个延时功能的挂起函数，普通函数无法调用。我们给 block()加上suspend则可以正常调用。

挂起函数不会阻塞当前线程，而是会将当前协程挂起，在适当的时候恢复。拿delay()函数来说，类似于java中的Thread.sleep(),但Thread.sleep()会阻塞当前线程，使得当前线程只能等待不能干其他事，而delay()只是将当前协程挂起，所在线程仍然可以去干其他事，等待时间到了又会恢复所在协程继续执行。因此协程能大大提高资源利用率。

CoroutineContext

即协程上下文。从上面的例子中我们了解到launch和async方法可以选择不传，而withContext则要求必须指定。协程上下文可以看做是一组用户用于定义该协程特征的参数集合，包括协程的拦截器、线程调度器、异常处理器、指定协程名称、协程生命周期Job等。

interface CoroutineContext {
    // 重载"[]"操作
    operator fun <E : Element> get(key: Key<E>): E?
    // 提供遍历当前 context 中所有 Element 的能力
    fun <R> fold(initial: R, operation: (R, Element) -> R): R
    // 重载 "+"操作,如果key一样则右边取代左边的。因此没有交换律。
    operator fun plus(context: CoroutineContext): CoroutineContext
    // 获取当前指定key外的其他上下文
    fun minusKey(key: Key<*>): CoroutineContext

    interface Element : CoroutineContext {
        val key: Key<*>
    }

    interface Key<E : Element>{}
}

可以看到每个Element都有一个索引，类似map一样的数据结构，且重载了[] + 运算符，可以方便的操作。

Dispatchers

即线程调度器，可以指定协程在哪个线程中执行，可选类型如下：

  • Dispatchers.Default：适合用于执行占用大量 CPU 资源的任务 ，如复杂计算 ，数据解析等。
  • Dispatchers.IO：适用于高并发的任务，如网络请求等 。
  • Dispatchers.Main：用于Android主线程中。
  • Dispatchers.Unconfined ：对当前线程不做限制 。

Job

协程启动后会返回一个Job对象，可以通过 coroutineContext[Job] 表达式从上下文中获取到，用于控制协程的生命周期。

Job 具有以下几种状态值，每种状态对应的属性值各不相同

State isActive isCompleted isCancelled
New (optional initial state) false false false
Active (default initial state) true false false
Completing (transient state) true false false
Cancelling (transient state) false false true
Cancelled (final state) false true true
Completed (final state) false true false

CoroutineStart

协程的启动模式。以下几种类型：

  • CoroutineStart.DEFAULT：协程创建后立即开始调度，在调度前如果协程被取消，其将直接进入取消响应的状态，虽然是立即调度，但也有可能在执行前被取消；
  • CoroutineStart.ATOMIC：协程创建后立即开始调度，协程执行到第一个挂起点之前不响应取消，如其名字一样是原子操作，因此一定会执行；
  • CoroutineStart.LAZY： 只有主动调用该协程的start、join或者await等函数时才会开始调度，如果调度前就被取消，协程将直接进入异常结束状态；
  • CoroutineStart.UNDISPATCHED：协程创建后立即在当前函数调用栈中执行，直到遇到第一个真正挂起的点，保证立即执行且一定能执行；

总结

了解了协程的定义及优势，介绍了几种协程创建的方法和一些概念：

  • GlobalScope.launch可在任何地方创建，由于是顶层协程 ，不建议用，除非很明确就是要创建顶层协程 ；

  • runBlocking同样可在任何地方创建，但会阻塞线程，一般用于测试，实际中不会用；

  • coroutineScope用于创建一个独立的协程作用域，可以在协程作用域或者挂起函数中调用；

  • launch必须在协程作用域中才能调用;

  • async可以返回协程执行结果，实现类似两个任务都返回后统一回调的功能；

  • withContext可以理解为async的一种 简化版写法，一般用于指定线程参数；

  • 协程上下文是一组用于定义协程生命周期、运行线程、名称、异常等特性的参数集合；

  • 协程启动有四种模式，可根据需要进行选择。
